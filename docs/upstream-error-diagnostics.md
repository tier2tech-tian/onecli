# 上游错误与账号轮换诊断

网关为每次转发生成 request_id，并在 request_logs.extra_data.upstream 保存候选数量、零起始下标、轮换原因、最终状态和 attempts。每次尝试含 secret_id（账号记录标识，非密钥）、UTC时间、HTTP状态、到响应头耗时，以及 error 下的错误类型、文案和允许的限流响应头。网络失败没有上游HTTP状态，记null，并单列网关502；不会继续轮换。

记录范围：JSON的error.message/message、error.type/code及纯文本错误；错误正文最多采样8KiB、最多等待250ms，文案最多2048字符，先过滤已知注入凭据和常见认证标识。任意请求字段、HTML、成功回复正文不入库。超限、慢响应、解析失败均记录capture原因，不用通用文案冒充上游原文。采样过的响应块完整重放，正常成功流不预读正文；成功响应也保存允许的请求ID/限流头。

轮换策略不变：按Agent与host维护起点，每次请求加一，只有429才尝试下一候选，每个请求最多尝试候选数量次。单候选、无候选、已知超过4MiB仍单次发送；没有冷却机制。数据库只增加既有extra_data内容，无迁移。成功换号也保留前面429的文案。

限制：仅适用于HTTP转发尝试；HTTP 200内部的流式错误事件、WebSocket帧错误不解析。网关本地生成的策略拒绝/鉴权提示沿用旧日志，不能冒充上游错误。超大/超慢/非支持格式错误可能没有文案，但会保留采样原因。日志队列仍沿用现有有界异步机制，队列满或数据库故障不保证零丢失。历史记录没有正文，部署后不能补回。

验证：cargo test --locked。完整HTTP转发与真实Postgres验证另设环境变量ONECLI_DIAGNOSTIC_TEST_DB，运行 real_forwarding_persists_attempt_chain ignored测试；必须使用独立临时数据库，不连接生产。覆盖429→200、全429、429→401、单候选403、超4MiB单次429、429后断连，以及审批原行更新。单测覆盖小写认证脱敏、慢流重放、大正文和HTML不采集、成功流原样保留。
